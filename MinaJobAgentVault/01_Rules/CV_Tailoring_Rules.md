# CV Tailoring Rules

> ⚠️ CRITICAL: Load this file before EVERY CV generation task.

## The Golden Rule
**NEVER invent anything.** Every line in a tailored CV must be traceable to `Base_CV.md`.

## What IS Allowed
- ✅ Reorder bullet points to match job requirements
- ✅ Use stronger action verbs (built → architected, helped → led)
- ✅ Add keywords from job description IF Mina genuinely has that skill
- ✅ Expand or compress the profile summary for the role
- ✅ Highlight the most relevant experience section first
- ✅ ATS keyword optimization (place keywords naturally in existing bullets)

## What is NOT Allowed
- ❌ Fabricate companies, roles, or dates
- ❌ Claim skills Mina doesn't have (no "Terraform" if not in base CV)
- ❌ Add years of experience Mina doesn't have
- ❌ Invent project names or outcomes
- ❌ Claim certifications not in the base CV
- ❌ Use vague inflated language ("decade of experience")

## ATS Optimization Rules
1. Use exact keywords from the job description where truthful
2. Spell out abbreviations once: ".NET (ASP.NET Core)"
3. Use standard section headers: Experience, Education, Skills
4. No tables or columns (ATS can't parse them)
5. No images or icons
6. Use bullet points, not paragraphs, for experience

## Structure Order for Tailored CVs
1. Name + contact
2. Profile summary (tailored 3–4 lines)
3. Skills (reordered by job relevance)
4. Work Experience (most relevant first)
5. Education
6. Languages
